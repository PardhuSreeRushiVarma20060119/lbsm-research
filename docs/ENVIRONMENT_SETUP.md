# Environment Setup

LBSM has **three parallel ways to get a working Python environment**, plus a separate,
independent R track. This doc explains what each one does, how they relate to each other, and
which one to reach for. Nothing here is aspirational — every claim below was checked directly
against the actual `flake.nix` / `environment.yml` / `pyproject.toml` / `setup.cfg` / `Makefile`
in this repo, not assumed from convention.

## The three Python paths, at a glance

| Path | Command | Python | Has SageMath | Canonical? |
|---|---|---|---|---|
| **Nix** | `nix develop` | 3.13 | Yes | Yes — this is what CLAUDE.md calls the canonical dev shell |
| **conda** | `conda env create -f environment.yml` | 3.12 | No | Compatibility alternative for non-Nix users |
| **pip/venv** | `pip install -r requirements.txt` | 3.12+ | No | No-Nix fallback; `requirements.txt` is *generated by* the Nix path, not hand-maintained |

All three install the same core scientific stack: `numpy`, `pandas`, `scipy`, `scikit-learn`,
`matplotlib`, `seaborn`, `jupyterlab`/`notebook`, `ipykernel`, `plotly`, `umap-learn`,
`hmmlearn`. The only thing that's genuinely Nix-exclusive is **SageMath** (`paper/math-supplementry/`
needs it) — conda and pip users can run every notebook (`01`-`06`) but not the SageMath math
appendix.

## Path 1 — Nix (`nix develop`)

This is the canonical path (`README.md`/`CLAUDE.md` both point here first). Defined entirely in
`flake.nix`:

```nix
packages = with pkgs; [
  python313 python313Packages.pip python313Packages.numpy python313Packages.pandas
  python313Packages.scipy python313Packages.scikit-learn python313Packages.matplotlib
  python313Packages.seaborn python313Packages.jupyterlab python313Packages.plotly
  python313Packages.notebook python313Packages.ipykernel python313Packages.umap-learn
  python313Packages.hmmlearn
  sage   # required for paper/math-supplementry/
];
```

Supported systems: `x86_64-linux`, `aarch64-linux`, `x86_64-darwin`, `aarch64-darwin`.

**Every time you run `nix develop`, its `shellHook` regenerates `requirements.txt` from
scratch** — it `echo`s a header, then a heredoc listing every package above except `sage`, then
prints `✓ requirements.txt synced.`. This is why `CLAUDE.md` says not to hand-edit
`requirements.txt`: any manual edit is overwritten on the next `nix develop`. `sage` is
deliberately excluded from the generated file — the comment in `flake.nix` explains why: *"CI
dependency submission validates this list against PyPI, and SageMath is provided via
Nix/system"* — i.e. `requirements.txt` is also consumed by a GitHub dependency-submission check
that expects every line to resolve on PyPI, and SageMath isn't a PyPI package.

**Known gotcha (fixed as of this writing, kept here for context)**: `requirements.txt` as
committed at `d7b35f0` had a SageMath REPL banner (box-drawing characters plus a stray `sage:`
prompt line) corrupting the comment after `hmmlearn` — evidence the shellHook's heredoc got
interleaved with literal Sage banner output at some point before that commit. This has since
been cleaned up locally. If it recurs: the shellHook always starts with
`echo ... > requirements.txt` (a full overwrite), so simply re-entering `nix develop`
regenerates the file cleanly — no manual cleanup needed.

```bash
nix develop              # canonical dev shell
# or, via Makefile:
make shell                # identical — `make shell` is just `nix develop`
make notebook              # jupyter lab, once inside the shell
```

## Path 2 — conda (`environment.yml`)

```bash
conda env create -f environment.yml
conda activate lbsm
```

`environment.yml` header says it plainly: *"Compatibility environment for non-Nix users.
Canonical environment definition lives in flake.nix."* Two concrete differences from the Nix
path worth knowing:
- **Python 3.12**, not 3.13 (Nix's `python313`).
- **No SageMath** — the math-supplementary notebooks/appendix won't run under this environment.

Otherwise the package list is identical to the Nix path's non-Sage packages, kept in sync by
hand (there's no automation tying `environment.yml` to `flake.nix` the way `requirements.txt`
is auto-synced — if the Nix package list changes, `environment.yml` needs a manual matching
edit).

## Path 3 — plain pip / venv (`requirements.txt`)

```bash
python -m venv .venv
source .venv/bin/activate     # or .venv/bin/activate.fish, etc.
pip install -r requirements.txt
```

`pyproject.toml` sets `requires-python = ">=3.12"`, matching conda's floor. This is the
simplest path and what a plain CI runner or a contributor without Nix/conda would use — but
remember `requirements.txt` is *generated output* (see Path 1's gotcha above), not a
hand-authored dependency list; if you need to add a package, edit `flake.nix`'s `packages` list
and regenerate via `nix develop`, don't edit `requirements.txt` directly even under this path.

This repo already has a `.venv/` checked out locally, built from a Nix-provided Python 3.12
interpreter (`.venv/pyvenv.cfg` points `home` at a `/nix/store/.../python3-3.12.13/bin` path) —
i.e. even the "plain pip" path here was bootstrapped using a Nix-supplied Python rather than a
system one, though nothing about the venv itself is Nix-specific once created.

## The `src` editable install

None of the three paths above install the `src` package itself — that's a separate step, driven
by `pyproject.toml`:

```toml
[build-system]
requires = ["setuptools>=61"]
build-backend = "setuptools.build_meta"

[tool.setuptools.packages.find]
where = ["."]
include = ["src*"]
```

Running `pip install -e .` (from any of the three environments) makes `import src.<module>`
work from notebooks/experiments without `sys.path` hacks — this is what `lbsm.egg-info/`
(present in this checkout) is evidence of: an editable install has been done here at least
once. `setup.cfg` duplicates the same package metadata in the older `setup.cfg`/`setuptools`
style (name, version, description, `packages.find` with the same `include = src*`) — the two
files describe the same install, `pyproject.toml` is the modern PEP 621 entry point setuptools
actually reads; `setup.cfg` looks like a carried-over legacy duplicate rather than something
actively maintained separately, worth being aware of if the two ever drift (e.g. version bumps
applied to one and not the other).

## Makefile targets and what environment they assume

```makefile
install:  pip install -r requirements.txt   # assumes you're already inside SOME environment
shell:    nix develop                        # Nix-specific
notebook: jupyter lab                        # assumes jupyterlab is on PATH (any of the 3 paths)
test:     pytest tests/
lint:     ruff .
format:   black .
clean:    remove __pycache__ / *.pyc
```

`install`, `test`, `lint`, `format` don't care which of the three paths you're in — they just
assume the relevant tool (`pip`, `pytest`, `ruff`, `black`) is already on `PATH`, which is true
inside any of the three activated environments. `shell` is the one target that's Nix-only.
Neither `ruff` nor `black` has a config section in `pyproject.toml`, so both run with their
default settings — nothing repo-specific to know there beyond `setup.cfg`'s `[flake8]` section
(`max-line-length = 100`, a few ignored codes), which is unrelated to the `make lint`/`make
format` tools actually wired up (flake8 itself isn't invoked by any Makefile target).

## The R track — separate from all of the above

`r/` (statistics/, visualization/, reports/) is an **independent track**, not wired into any of
the three Python environments or the Makefile. Per `CLAUDE.md`: run manually via `Rscript` or
RStudio. This checkout already has `.RData`/`.Rhistory` at the repo root, meaning R has been
used interactively here before — but there's no `renv.lock`/equivalent dependency manifest for
R in this repo, so reproducing that environment on a fresh machine isn't currently automated the
way the Python side is.

## Which one should you actually use?

- **Default to Nix** (`nix develop` / `make shell`) unless you have a concrete reason not to —
  it's the only path with SageMath, it's what `requirements.txt` is generated *from* (so it's
  authoritative if the paths ever disagree), and it's what the project's own docs point to
  first.
- **Use conda** only if Nix isn't available on your machine and you'd rather manage the
  environment with conda than pip/venv — functionally equivalent to Path 3 minus SageMath, on
  Python 3.12 instead of 3.13.
- **Use pip/venv** for the lightest-weight setup (e.g. a CI runner, or a quick check) — same
  caveat as conda (no SageMath), and remember `requirements.txt` isn't meant to be hand-edited.
- Either way, don't forget `pip install -e .` (or equivalent for your environment) to get
  `import src.*` working — none of the three environment definitions do this for you
  automatically.
